# Keycloak 26 core PII profile

Status: conformance corpus included; full Keycloak runtime E2E is required before using a specific 26.x release in production.

This profile protects the fixed PII columns in `public.user_entity`. `username` and `email` use deterministic encryption because Keycloak performs exact equality lookups. `first_name` and `last_name` use randomized encryption and therefore cannot be searched through the gateway.

The profile intentionally does not claim coverage for `user_attribute`, credential documents, custom providers, extension tables, Liquibase or administrative substring searches. Conditional row policies are not part of policy version `pgkms.dev/v1`; encrypting only attributes whose names match a prefix therefore requires a future policy version or a separate table design. Do not silently pass those writes.

Before deployment:

1. Pin an exact Keycloak container digest.
2. Export the schema generated by that release and confirm every protected column identity and type.
3. Add dedicated blind-index columns if the local query corpus requires randomized equality search.
4. Build a sanitized runtime SQL corpus from login, registration, account, admin and password-reset flows.
5. Run `corpus-verify`, TLS/SCRAM E2E, backfill and deep verification.
6. Keep Liquibase on a separate migration connection that cannot serve application traffic.

The encrypted endpoint blocks DDL, joins involving protected relations, function-wrapped protected predicates, protected literals and unsupported search forms. This is deliberate fail-closed behavior.
